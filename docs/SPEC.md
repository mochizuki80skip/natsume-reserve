# 接骨院 WEB予約システム 仕様書

2026-09-15 時点でヒアリング確定した内容をまとめたもの。設定値として持たせる項目は
「設定」と明記しており、あとから管理画面（または本部設定）で変更できる。

## 1. 全体構成

```
顧客（スマホ/PC）                      接骨院スタッフ（PC/タブレット）
   │  https://<domain>/s/<店舗コード>        │  https://<domain>/admin
   ▼                                        ▼
 顧客サイト（〇×表示・予約フォーム）      管理サイト（Excel風の予約表・カレンダー・設定・印刷）
   │  空き状況は 〇 / × / 電話 のみ返す     │  店舗コード＋パスワードでログイン
   ▼                                        ▼
            サーバー（Next.js on Vercel） ─── PostgreSQL（Supabase 等）
                                       └── SMS（Twilio）で予約確定を自動送信
```

- 24店舗を 1 つのシステムで管理する。店舗ごとに店舗コードを持ち、
  顧客用 URL は `/s/<店舗コード>`、管理画面は店舗コード＋パスワードでログインする。
- 本部アカウント（role = hq）は全店舗の予約表・カレンダー・設定を横断して閲覧・編集できる。
- 顧客サイトには患者様の氏名など個人情報を一切返さない（API の応答は〇×と残枠のみ）。

## 2. 営業時間・休診日

| 項目 | 内容 |
|---|---|
| 枠の刻み | 15分（設定） |
| 平日（月火水金） | 9:00〜11:45 / 15:00〜19:15（最終枠の開始時刻） |
| 土曜 | 9:00〜11:45 / 14:00〜18:15 |
| 定休日 | 木・日・祝日（設定） |
| 統一日 | 2026-10-21 から全店舗で上記の営業時間に統一。それ以前は店舗ごとの営業時間（店舗設定の「営業時間の個別設定」）を使える |
| 臨時休診 | 管理画面のカレンダーで日付ごとに設定 |

営業時間は「期間 → 曜日 → セッション（開始〜最終枠開始）」の形で保存する。

```json
{
  "periods": [
    {
      "from": "2026-10-21",
      "byWeekday": {
        "1": [["09:00", "11:45"], ["15:00", "19:15"]],
        "2": [["09:00", "11:45"], ["15:00", "19:15"]],
        "3": [["09:00", "11:45"], ["15:00", "19:15"]],
        "5": [["09:00", "11:45"], ["15:00", "19:15"]],
        "6": [["09:00", "11:45"], ["14:00", "18:15"]]
      }
    }
  ]
}
```

曜日番号は 0=日 … 6=土。載っていない曜日は休診。

## 3. 顧客サイト

1. 来院区分を選ぶ：①はじめての方／1ヶ月以上ご来院の無い方　②ご通院中の方
2. カレンダーから日付を選ぶ（店舗が公開している日だけ選べる）
3. 時間ごとの空き状況を選ぶ
   - 〇 … WEB予約できる
   - 📞（電話マーク）… 残り枠が少ない／直前のためお電話で受付（店舗の電話番号を表示）
   - × … 空きなし／受付終了
4. 情報を入力して予約
   - ①：氏名・電話番号
   - ②：診察券番号・氏名・電話番号（診察券番号は入力のみで照合しない）
5. 即時確定。確定内容を SMS で自動送信する（設定で本部・店舗宛の通知も可）

### 空き判定ルール

- 顧客に見せる枠数 ＝ その日のシフトに入力した施術者の人数（未入力の日は店舗設定の既定値）。
  管理側はベッド数（8列）のどこにでも入力できるが、ある時刻に埋まっているベッド数が施術者数に達した時点で顧客には×になる。
- ②通院中：その時刻のセルが空いているベッドが 1 台以上あれば空き。
- ①初回：同じベッドで「希望時刻」と「その15分後」の 2 枠が連続して空いていれば空き
  （連続枠数は設定。午前の最終枠など次の枠が営業時間外のときは不可）。
- 残り枠数が「電話マークにする残り枠数」（設定、初期値 1）以下なら 〇 ではなく電話マーク。
- 当日：開始 30 分前まで WEB 予約可（設定）。30 分前〜15 分前は電話マーク（設定）。15 分前以降は ×。
- 同じ枠への同時アクセスはサーバー側でトランザクション＋行ロックにより二重予約を防ぐ。
- ①の予約は 2 枠を使うので、予約表には 1 枠目に氏名、2 枠目に「〃」を書き込む。

### キャンセル・変更

- 顧客サイトからのキャンセルは不可（電話のみ）。SMS 本文に店舗の電話番号を記載する。
- 将来 WEB キャンセルを追加する場合は予約 ID を使ったキャンセル URL を SMS に載せる想定。

## 4. 管理サイト

### 予約表（Excel 風）

- 1 日 1 画面。行 = 15 分の時間枠（午前／午後）、列 = ベッド 1〜8（店舗設定で変更可）。
- セルに直接入力できる。Excel からのコピー＆ペースト（複数セル、タブ区切り・改行区切り）に対応。
- 矢印キー・Enter・Tab でセル移動。入力内容は自動保存。
- 「本日のシフト」欄に施術者（最大 6 名）・受付（最大 4 名）の氏名を入力する。
  施術者の人数が顧客に見える空き枠数になる。最大人数は店舗設定で変更できる。
- 施術者数を超える列は灰色で表示されるが入力はできる（人員と稼働ベッドが一致しなくても管理側は予約を入れられる）。
- 午前〇名／午後〇名／合計を自動表示（氏名が入ったセル数。「〃」「✖」「×」は数えない）。
- 「2026年10月21日（水）」のように日付と曜日を表示。
- 前日／翌日／日付指定で移動。

### カレンダー

- 月表示。日付ごとに「公開」「非公開」「臨時休診」を切り替える。
- 既定は「今日から N 日先まで公開」（N は店舗設定、初期値 30）。個別設定が優先。
- 顧客サイトには公開日だけが選択できる状態で表示される。

### 印刷・PDF

- 「印刷／PDF」ボタンで A4 縦 1 枚に予約表（氏名入り、午前/午後人数付き）を出力する。
  ブラウザの印刷ダイアログから「PDF に保存」も可能。
- 営業終了後に当日分を印刷する運用を想定（`/admin/print/<日付>` を直接開ける）。

### 設定

- 店舗：店舗名・電話番号・ベッド数・既定の稼働台数・公開日数・営業時間の個別設定・
  店舗宛 SMS 通知先・パスワード変更。
- 本部：全店共通設定（枠の刻み、必要枠数、締切分数、電話マーク閾値、祝日休診、保持日数、営業時間）、
  店舗の追加・停止、店舗パスワードの再設定。

## 5. 通知

| 手段 | 実装 | 費用感 |
|---|---|---|
| SMS（Twilio） | 予約確定時に顧客の携帯番号へ自動送信。環境変数未設定時はログ出力のみ | 1通あたり約 10 円 |
| 店舗への通知 | 店舗設定の通知先番号に SMS（任意） | 同上 |
| メール | 顧客の連絡先は電話番号のみのため未実装。必要になれば送信サービスを追加 | ほぼ無料 |

SMS 本文の例：

```
【〇〇接骨院】ご予約を承りました。
10月21日(水) 15:00〜
はじめての方は10分前にお越しください。
変更・キャンセルはお電話（055-000-0000）へお願いします。
```

## 6. セキュリティ・個人情報

- 通信はすべて HTTPS。
- 顧客向け API は空き状況（〇×電話）のみを返し、氏名・電話番号・診察券番号は返さない。
- 管理画面はログイン必須。パスワードは bcrypt でハッシュ化。セッションは署名付き Cookie（HttpOnly / Secure / SameSite=Lax）。
- 店舗アカウントは自店舗のデータにしかアクセスできない（サーバー側で店舗 ID を必ず絞り込む）。
- 予約 API は同一 IP からの連続リクエストを制限する。
- 個人情報（予約・予約表のセル）は 2 ヶ月（設定）で自動削除する（毎日 3:00 JST のバッチ）。
