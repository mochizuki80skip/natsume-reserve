# 別の事業体に合わせる

変える場所の一覧は **`docs/CUSTOMIZE.md`**、作りは `docs/DESIGN.md`、設置は `docs/OPERATIONS.md`。
このスキルは「どの順で・何を確かめながら進めるか」をまとめたものです。各段階の最後に、依頼者へ見せて確かめてもらいます。

## 0. 始める前に

- 元のプロジェクト（なつめ接骨院グループ）は**そのまま動かし続ける**。作り替えは新しいリポジトリで行い、元のリポジトリには展開先の名前・データを入れない。
- 元の本物の患者様のデータ（DB・画面写真・CSV）は、新しいプロジェクトに**持ち込まない**。
- 依頼者は技術者ではない。質問は「例を挙げて選んでもらう」形にし、大きな変更はラフ（HTML）を見せてから作る。

## 1. 聞き取り（`CUSTOMIZE.md` §1 の 15 項目）

依頼者に聞き取りシートを渡し、答えをもらう。最低限そろえるもの：

1. 事業体の名前・店舗の数・ドメイン
2. 1 枠の長さ（15 分など）と、1 回の予約で使う枠の数（区分ごと）
3. 営業時間・定休日・祝日の扱い
4. 予約の区分（初めて／2 回目以降／久しぶり など）と、区分ごとに必要な入力（会員番号など）
5. ベッド・席・部屋など「同時に受けられる数」の単位と、担当者の決まり
6. メニュー・オプション・物販
7. 使う機能（新患継続率・離反者・窓口集計・日報・自賠請求・SMS・LINE 通知 など）
8. お客様の呼び方（患者様／お客様／生徒さん）と、注意書き・プライバシーポリシーの内容

答えから「今の作りのままでよい所」と「作りを変える所」を表にして依頼者に見せる。

## 2. 新しいリポジトリを作る

```bash
# 元のリポジトリの xserver/ だけを、履歴なしで新しいフォルダへ
git -C <元のリポジトリ> archive HEAD xserver | tar -x -C <作業場所>
cd <作業場所>/xserver && git init && git add -A && git commit -m "元の予約システムから分けて開始"
```

- `app/config.php`・`public/version.json` の `2099` 版・テストの一時ファイルが入っていないことを確かめる。
- `.github/workflows/deploy-xserver.yml` は元のリポジトリのいちばん上にあるので、使うなら新しいリポジトリの `.github/workflows/` へ写し、`xserver/` のパスを外す。
- `CLAUDE.md` の 1 行目と説明を新しい事業体の名前に直す。

## 3. 作りの整理を先にするか決める（`CUSTOMIZE.md` §9）

| 展開先の区分・印・枠 | すること |
|---|---|
| 区分が今と同じ 4 つ以下で、2 枠までで足りる | 整理なしで進めてよい（区分を減らすのは画面の選択肢から外すだけ） |
| 区分を足す・意味を変える | **先に** 区分の定義を `app/lib/Kinds.php` と `frontend/src/lib/kinds.ts` にまとめ、印の規則もそこから作る |
| 1 回で 3 枠以上使う | **先に** 「続きのセル」を数で扱う形に直す |
| 機能をいくつも外す | 機能の ON/OFF を `global_setting` に持たせる |

整理は 1 つずつ行い、そのたびに**全部の確認テストが通ってから**次へ進む（整理だけで動きが変わらないこと）。

## 4. 順に合わせ込む

それぞれ `CUSTOMIZE.md` の節を開き、表の場所をすべて直す。1 段階ごとにコミットする。

1. **名前・ブランド**（§2）：グループ名（画面・メールの送り主・SMS・通知・プライバシーポリシー）、色、保存名 `natsume.*`、Cookie 名。`grep -rn "なつめ\|natsume" app frontend/src public e2e` で残りが無いか確かめる。
2. **時間**（§3）：`Hours::defaultHours` の初期の営業時間、`global_setting` の初期値（`slotMinutes`・`newVisitSlots`・`returnVisitSlots`・締め切り）、祝日休み。
3. **区分と印**（§4）：区分の名前（お客様用・スタッフ用）、区分ごとの入力、セルの印。PHP（`Text.php`・`PublicApi.php`）と TS（`attendance.ts`・`kindTag.ts`・`cellColor.ts`）を**必ずそろえる**。
4. **メニュー・選択肢**（§5）：`Karte::OPTION_DEFAULTS`、施術内容、n 回目の数え方。古い `Migrate` の選択肢の追加手順は、新しい DB では要らないので外してよい（`VERSION` は下げない）。
5. **機能**（§6）：使わない機能をメニューから外す（API はログインと権限で守られているので、まずはメニューから外すだけでもよい）。
6. **文言**（§7）：予約ページの説明・注意書き・SMS・通知の文・プライバシーポリシーのひな形・使い方（`lib/guide.ts`）。`changelog.ts` は空（または「運用開始」の 1 件）から始める。
7. **初期データ**（§8）：`Install.php` の見本の店舗と見本のパスワード。

DB の項目を足すときは、元と同じく `Migrate::VERSION` を上げて `schema.sql` も直す（`CLAUDE.md` の決まり）。

## 5. テスト

- `.claude/skills/e2e-test/SKILL.md` の手順で準備する。
- 区分・印・時間を変えると、多くのテストの「見本の文字」「時刻」「区分のボタン名」がずれる。テストを新しい事業に合わせて直す（テストを消したり飛ばしたりしない）。
- 単体テスト（`npx vitest run`）と、全部の e2e が通るまで直す。
- 画面写真（`public/guide/*.png`）は見本のデータで撮り直す。

## 6. 設置と引き渡し

- `docs/OPERATIONS.md` §1 の手順で新しいサーバーに入れる（`INSTALL_TOKEN` は設置後に空、`APP_ENV` は `production`）。
- 本部の画面で店舗・エリア・アカウントを作り、見本の店舗を消す。
- 依頼者に「試験運用 → 本番」の段取りと、確かめてほしいことの一覧を渡す。
- 更新ファイルは `.claude/skills/release-package/SKILL.md` で作る（最初はまるごと入れ、その後は差分）。
