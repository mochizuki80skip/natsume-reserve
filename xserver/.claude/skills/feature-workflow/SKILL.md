# 機能を足す・直す進め方

## 1. 受け取る

- 依頼の文が短い・途中で切れている・2 通りに読めるときは、例を挙げて確かめる（「ア：〜／イ：〜 のどちらですか」）。おすすめがあれば添える。
- 大きな機能（新しい画面・計算のルールが変わる・患者様の画面が変わる）は、**作る前にラフ**を見せる：
  - スクラッチパッドに 1 枚の HTML を作る（見本の名前・見本の数字。動く試作にすると伝わりやすい）。
  - `SendUserFile`（`display: render`）で送り、確認したいことを番号付きで聞く。
- 小さな直し（文言・表示のずれ・明らかな不具合）は、そのまま直してよい。

## 2. 作る

- 原因を調べ、**直す前に失敗を再現**する（再現用のスクリプトや e2e のテストで）。
- DB の項目を足す：`app/lib/Migrate.php` の `VERSION` を上げて `if ($ver < N) { … }` を足す。`hasColumn` / `hasTable` で何度動いても安全に。`app/sql/schema.sql` にも同じ項目をコメント付きで足す。
- API を足す：`app/routes.php` に 1 行、`app/handlers/*.php` に関数。役割の確認（`Auth::requireHq()`／`Auth::context()`）、`Http::requireJson()`、入力の検証（`Http::int`・`Http::str` など）を必ず入れる。
- 画面：`frontend/src`。テストで探せるよう、ボタン・入力欄に分かりやすい `aria-label` を付ける。スマホ（幅 390px）でも崩れないか見る。患者様のページの入力欄は文字 16px 以上（iPhone で拡大されないように）。
- 個人情報を外へ送る機能（メール・LINE・SMS）は、載せる内容を最小限にし、本部の設定で選べるようにする。

## 3. 仕上げる

- `frontend/src/changelog.ts` に更新のお知らせ（`id` を 1 つ上げる。`audience` は ['店舗'] / ['本部'] / ['経理'] から）。
- 操作が変わったら `frontend/src/lib/guide.ts` の記事を直す。画面写真（`public/guide/*.png`）が古くなったら撮り直す。
- `e2e/` にテストを足す・直す。関係するテストと、できれば全部を動かす（`.claude/skills/e2e-test/SKILL.md`）。
- コミットして push。メッセージは日本語で、何を・なぜ。モデル名は書かない。
- 更新ファイルを作って渡す（`.claude/skills/release-package/SKILL.md`）。

## 4. 返事の書き方

- やさしい日本語。何を直したか → 原因（不具合のとき）→ 依頼者がすること（アップロード・確認）の順。
- 実際に確かめたこと（テストの数、直す前に失敗したこと）を書く。確かめていないことは「確かめていません」と書く。
- 画面写真があると伝わりやすい（見本のデータで撮る）。
- 最後に必ず「**確認待ち・保留**」の一覧。終わったものは消し、依頼者が「止めておいて」と言ったものは「保管中」として別に残す。
