## 1. 設置（新しいサーバーに入れる）

くわしい手順は `README.md` の 1〜5 にあります。要点だけ：

| 順番 | すること | 場所 |
|---|---|---|
| 1 | ドメイン（できればサブドメイン）を作り、無料 SSL を ON | サーバーパネル |
| 2 | PHP 8.2 以上（動作確認は 8.3） | サーバーパネル「PHP Ver.切替」 |
| 3 | MySQL（MariaDB）のデータベースとユーザーを作る | サーバーパネル「MySQL設定」 |
| 4 | ビルド済みの一式（`public/` の中身と `app/`）を予約システム専用のフォルダに置く。`.htaccess` も忘れずに | FTP・ファイルマネージャー |
| 5 | `app/config.example.php` をコピーして `app/config.php` を作る（下の表） | 同上 |
| 6 | `https://ドメイン/install?token=INSTALL_TOKEN` を開いてテーブルを作る | ブラウザ |
| 7 | `config.php` の `INSTALL_TOKEN` を `''` にする（初期設定ページを無効に） | FTP |
| 8 | Cron に毎日の自動削除を登録する | サーバーパネル「Cron設定」 |
| 9 | 本部（`/admin/login`、コード `HQ`）で店舗・エリア・アカウントを作り、見本の店舗を消す | 管理画面 |

### config.php の項目

| 項目 | 入れる値 | 注意 |
|---|---|---|
| `DB_HOST` `DB_PORT` `DB_NAME` `DB_USER` `DB_PASS` | MySQL の情報 | |
| `SESSION_SECRET` | 32 文字以上のランダムな英数字 | 変えると全員ログインし直し。見本のまま（change-me）だと本部の画面に警告が出る |
| `HQ_PASSWORD` | 本部アカウント HQ の最初のパスワード | 最初のログイン後に変える |
| `INSTALL_TOKEN` | 初期設定ページの合言葉 | **設置後は必ず空にする** |
| `CRON_SECRET` | 自動削除の合言葉（8 文字以上） | |
| `APP_URL` | 正式な URL（例：`https://yoyaku.example.jp`） | ほかの URL から開かれたら転送。通知のリンクにも使う |
| `APP_ENV` | `'production'` | `development` にすると画面にエラーの中身が出る（本番では使わない） |
| `MAIL_FROM` | 通知メールの送り主（空なら `no-reply@APP_URL のドメイン`） | 迷惑メールになるときは、そのドメインで実在するアドレスにする |
| `MAIL_LOG` | 空のまま | テスト用：入れるとメール・LINE を送らずにそのファイルへ書く |
| `TWILIO_*` | SMS を使うときだけ | 有料 |

`config.php` は Git にも更新ファイルにも入れません。サーバーの上でだけ作ります。

## 2. 更新（新しい版を入れる）

### A. 更新ファイル（zip）を手で上げる（今の主なやり方）

開発側が `scripts/make-update.sh` で `update-MMDDx.zip` を作ります（`.claude/skills/release-package/SKILL.md`）。

| 順番 | zip の中のフォルダ | 上げる先 |
|---|---|---|
| 1 | `1_assets` の中身 | `assets` フォルダ |
| 2 | `2_app` の中身 | `app` フォルダ（上書き） |
| 2 | `2_guide` の中身 | `guide` フォルダ |
| 3 | `3_root` の 3 つ（`index.html`・`version.json`・`index.php`） | いちばん上のフォルダ（**最後に**） |

- 上げたら、管理画面の右下の「**画面の版**」が zip と同じ日時になっているか確かめる。
- 開いたままの画面には「画面が新しくなりました」の帯が出て、押すと新しい画面になる。
- DB の項目が増える版でも、最初のアクセスで自動で足されます（`Migrate`）。`/install` の再実行は要りません。
- zip はそれまでの変更をすべて含むので、途中の zip を上げ忘れても、最新の zip だけを上げれば大丈夫です。

### B. GitHub から自動で反映する

`.github/workflows/deploy-xserver.yml` が、`main` に push するたびにビルド・テストして zip を作り、SSH の Secrets があればサーバーへ送ります（`README.md` の 6-A）。

## 3. 毎日の自動処理（Cron）

```
/usr/bin/curl -s "https://ドメイン/api/cron/cleanup?token=CRON_SECRET" > /dev/null
```

- 予約表のセル・シフト・ブロックなどを、保持日数（既定 60 日、本部で変更）を過ぎたら消します。WEB 予約の記録・キャンセル名簿・新患継続率は消しません。
- 自賠請求の明細の氏名も、保持期間（既定 180 日）を過ぎたら消します（金額は残る）。
- 止めておきたいとき（試験運用中など）は Cron を登録しないでおく。

## 4. 通知の準備（任意）

| 通知 | 準備 | 料金 |
|---|---|---|
| 新自（交通事故）の来院を LINE で知らせる | LINE 公式アカウント（通知専用）を作り、チャネルアクセストークン・チャネルシークレットを本部の画面に入れ、Webhook URL `https://ドメイン/api/line/webhook` を登録。送り先は 6 桁の番号で登録 | 無料プランは月 200 通まで（超えた月は送られないだけ） |
| 同じ内容をメールで | 本部の画面で送り先のメールアドレスを入れ、「試しのメールを送る」 | 無料（サーバーのメール） |
| WEB 予約が入ったら SMS | `TWILIO_*` を入れる | 有料 |

LINE の準備の細かい手順は、依頼者向けの資料「新自の通知 LINE公式アカウント準備の手順」にあります。

## 5. バックアップ

- **データベース**：サーバーパネルの「MySQL バックアップ」または phpMyAdmin の「エクスポート」で、月 1 回以上と大きな更新の前に保存する。
- **config.php**：サーバーから手元へコピーして安全な場所に保管する（DB のパスワードと SESSION_SECRET が入っているため、共有フォルダには置かない）。
- プログラムは Git にあるので、バックアップは要りません。

## 6. 困ったとき

| 起きたこと | 見るところ |
|---|---|
| 画面が真っ白・「サーバーでエラー」 | サーバーパネルの「エラーログ」。`[api]` で始まる行に原因が出る |
| 画面の URL が 404 | `public` の `.htaccess` が置かれているか |
| 更新したのに古い画面のまま | 「画面の版」を確かめる。違えば `3_root` を上げ直す。ブラウザで再読み込み |
| ログインできない（全員） | `SESSION_SECRET` を変えていないか。`config.php` が消えていないか |
| パスワードを 10 回間違えた | 10 分待つ（店舗ごと・IP ごとに一時停止） |
| WEB で予約が取れない | 本部・店舗の「使い方」→「よくある質問」。シフト・臨時休業・ブロック・公開中か・WEB で同時に受ける人数 |
| 通知が届かない | LINE：本部の画面で「登録済み」になっているか、今月の通数。メール：迷惑メールのフォルダ、`MAIL_FROM` |
